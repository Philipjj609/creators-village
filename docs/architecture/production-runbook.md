## Startup, monitoring and rollback

- Migration command takes the advisory migration lock and verifies canonical LF/historical CRLF checksums. Application startup never migrates: it requires exact schema/reader/source/asset fingerprints, non-DDL role, PostgreSQL17+, exact HTTPS callback and explicit gameplay write disposition. Wrong local entrypoint refuses production.
- `/livez`: process/drain state. `/readyz`: startup fences succeeded and PG accessible;503 otherwise. Existing `/health` retains sanitized retention state. Monitor readiness, restarts/OOM, PG capacity/connections, sanitized failed commands, completion jobs pending/leased/blocked and retention warning age. A stale session must revalidate via real Twitch; provider trouble fails authenticated actions closed rather than blocking the whole startup scan. Never log auth query strings, tokens, invitation URLs or rosters. Review provider-generated access-log/query retention separately;14-day app logs are not a claim about provider logs.
- SSE retains existing bounded buffering, heartbeat and replay. Responses are `text/event-stream`, `no-store`, `X-Accel-Buffering:no`. Clients must reconnect; a deployment is not uninterrupted stream delivery. Public-origin stream/idle/reconnect behavior remains unverified.
- Before rollout: label backup, record commit+image digest+applied migration list and encryption-key version, prove restore in a separate database. Current PI2 adds no SQL migration. Review future migrations for compatibility before applying them while an older instance is serving.
- Rollback: set `GAMEPLAY_WRITES=paused` and deploy that environment, wait for old instance termination so no writer remains; retain a compatible WF2 reader. Restore the previously tested **compatible image**, still paused. Verify `/readyz`, owned/private readers, contribution receipts, replay and geography; reopen writes only after verification. Never overwrite accepted contributions with an older DB snapshot. Unsupported schema/reader fails closed; use a forward fix or reviewed repair/restore to a separate DB, not automatic down-migration. Do not roll back to pre-WF2 or the PI1 image lacking production web serving.
- SIGTERM drains SSE, waits bounded workers/pool and exits within30s; provider grace35s. SIGKILL can leave a durable30s lease; restart claims expired work atomically. Keep the previous image locally/privately; no remote image has been uploaded in PI2.

Public creator onboarding remains gated by failed-generation recovery and explicit legacy-v1 creation policy. Independent-person Twitch testing and the CV-S1 world-art gate are still pending. Hosted readiness must be earned after external configuration; local green checks are not a release declaration.
