# LW1.1 — bounded goals and camera motion

31 October 2026, adopted for local implementation under Philip's LW1.1 request. Supersedes fixed-route behavior for the new `lw1-goals-1` read projection; `lw1-routines-1` remains readable. No saved schema, identity, permission, construction, art manifest or production deployment changes.

The read-only server builds reachable interaction locations and cardinal routes using existing half-cell terrain/claim invariants. Residents choose among role-appropriate structure work, outdoor rest, inspection and a paired conversation. Selection scores explicit priorities, deterministic time-of-day and lightweight recency/fatigue/curiosity motivations. An action has choosing, travel, arrival, performing and completion phases. Completing an action updates the bounded local decision state before reevaluation. No randomness, reasoning model, rewards or simulated contributions.

Reconstruction uses independent four-minute shifts with bounded decision counts. Each shift begins and ends at the same resident rest point, with staggered decision delays. Finite utility choices vary by absolute shift/time and recent completed goals. Closing travel is reserved so shift boundaries remain continuous; it is not a teleporting reset. Paired residents reserve staggered conversation windows and route there before the shared start, face each other and perform only during their common interval. Invalid or unreachable pair positions disable that meeting. A new topology reconstructs immediately; old trajectories are not replayed.

The plan serializes at most four residents, four goals each and bounded pairwise routes. Client schedule caching retains at most two evaluated shifts per resident; it does not grow with offline duration. Evaluation of a century-old gap has the same bounded work as evaluation now. Current time still comes from the server plus monotonic elapsed client time.

Camera: replace fixed per-frame easing with the analytic critically damped spring described by [Ryan Juckett](https://www.ryanjuckett.com/damped-springs/). Use elapsed seconds for translation and logarithmic scale, zero overshoot for a stationary target, pointer-anchored zoom, drag acceleration/deceleration, bounded release velocity and a screen-space follow dead zone. Capture the prior overview before focus and restore it smoothly. Manual drag/wheel/keyboard cancels follow immediately. Reduced motion snaps and disables momentum. No CityRT login/access or proprietary source/assets needed.

Acceptance: meaningful role/world-dependent choices; explicit durations/completion; mutually coordinated social action; route/claim safety; same-time reload and bounded long-offline reconstruction; camera comparisons at 30/60/120 Hz, manual interruption/overview and reduced motion; integrated synthetic PostgreSQL/WF2/browser evidence. Player panels show supported facts and actions, with engineering caveats retained in documentation. Stop for product review. Hosted and judging fallbacks remain untouched.
