# WF1 implemented v2 contract

2026-10-29. project owner approved WF1 and the explicit development-slot policy in chat. This document records implementation, not future gameplay or artistic acceptance. See actual evidence (internal source record omitted), original proposal (internal source record omitted) and ADR-0004.

## Identity, format and authority

World UUID is allocated independently at accepted creation; seed is normalized NFC text, not a Twitch identifier. Provider identity remains in the existing person/session adapter. Header format2, generator `commons-geography-1`, frozen benchmark profile `gentle-512-32-2`, baseline hash and explicit `hearthside-hero-01/commons` appearance are persisted. The profile pins 256 XY units/tile, 1/16 tile corner heights, 32-cell chunks, 512-cell finite extent and a radius32 founding activation. These are one supported version, not permanent product limits. Future profiles require explicit readers; a saved world never loads through the newest generator.

The baseline contains256 immutable chunks. Each is exactly3202 bytes:33×33 little-endian signed16 height samples, then32×32 unsigned8 semantic cells. Water1, tree2, rock4, woodland cover8. Chunk SHA256 covers canonical uncompressed bytes. The baseline digest covers pinned generator/profile, normalized seed, landform, certificate and the ordered chunk hash manifest. Heights use the fixed NW-SE triangle split. Repeated borders are checked for equality. Feature identity is the baseline-bound cell coordinate/type; no resampling or object-per-ground-cell SQL table is needed. No tree regrowth/yields are implied.

Geography is a bounded gentle landform field: creek bend, lake edge or wooded ridge; static water; deterministic independent SHA256-framed coordinate streams and integer avalanche/noise; a bounded founding terrace and two meadow access corridors. It deliberately does not claim hydrological flow, erosion, arbitrary cliffs or bridges. Publication requires shelter support, initial arrival access, eight diagnostic3×3 opportunities and two reachable dry opportunities outside the active radius, toward west/north. Diagnostic candidate positions are not persisted as future plots. The initial path and stable `founding-shelter` are the only settlement structures; zero homes or synthetic accomplishments.

Certification failure fails closed; this implementation does **not** include the proposed eight-attempt/fallback search.200 seeds passed, but that corpus is not proof that every possible seed succeeds. A failed durable job remains visible and cannot silently change its seed. Transient expired-worker leases recover; explicit failed-job retry/reset policy remains an open operational limit for review before broader release. A future fallback must retain deterministic version/provenance, not patch existing saves.

Corner heights/cells and current relational facts are authority. `founding_structures` holds explicit quantized position/footprint/support height/entrance/template/appearance; exclusive half-cell `founding_occupancy` has composite same-world FK and unique keys; initial path geometry/width is relational. The stored header is an immutable founding projection. Read responses overlay authoritative structure/path/head values from one SQL statement snapshot; it cannot become a second mutable source of spatial authority. Natural cover does not grant construction permission. Administrative zones, functional districts, inhabitants and construction remain interfaces in the proposal, with no runtime policy/benefit implementation in WF1.

## Creation, persistence and recovery

`POST /api/founding`: existing authenticated confidential-server session + same Origin/CSRF safeguards; strict bounded `{commandId,name,seed,development}`; no client-selected UUID, purpose, template, terrain or balances. Name is trimmed and checked. The durable original202 receipt is `{jobId,worldId}`. Same principal/command/content repeats that acceptance; changed content or occupied slot conflicts. Status is queried separately at owner-only `GET /api/founding-jobs/:uuid`.

Person row and current session are locked for acceptance. One bounded worker consumes durable pending jobs, with a30s lease and10s worker timeout. Terrain generation is outside gameplay transactions in a Node worker. Publication locks the leased job, inserts world/header/all256 chunks/structure/24 half-cell claims/path/public founding event and marks ready in one transaction. A stale lease token cannot publish. Process loss leaves a reclaimable expired lease; mid-publication failure rolls back all ready geography. No request-time Blender or Twitch call is inside publication.

Additive migrations002/003 preserve every legacy table/row/reader/URL. New accounts keep one active world across formats. An account with v1 may explicitly request exactly one **private development/test** v2 slot, never a substituted active village. Existing `worldId` remains v1; `developmentWorldId` is separate. Development header/chunks and job status require the creator's session; anonymous access returns404. Active v2 and legacy villages retain existing public-by-link landscape semantics, without private account metadata. Database slot triggers also reject an old v1 writer attempting to bypass an occupied active v2 slot after application rollback. No unrestricted multi-world, ownership transfer or membership grants were introduced.

Migration checksums now normalize LF and accept the known historical CRLF equivalent without rewriting old migration records. Any substantive SQL change still fails checksum verification. New files are committed LF. The live v1 database was privately backed up/restored to a separate copy and migrated there before live application; original snapshot hashes stayed identical. Private copy was removed, ignored backup retained. No dump/session/credential data enters Git or Drive.

`GET /api/founding/:id` is version-aware and independent of `/api/villages/:id`. Missing/unsupported versions fail safely. Chunk endpoint takes at most64 validated keys, returns pinned baseline hash, cursor and persisted decoded chunks; stored payload hash/length is verified. Unknown/mismatching client geography fails to accessible inspection, not a regenerated world. Explicit `showcase-fern/willow/hearth/brook` are bounded reproducible examples with synthetic labels, not stored creator achievements or a way to create arbitrary production communities.

WF1 has one public founding event and immutable terrain; cursor1 does not expose private audit activity. HTTP bootstrap/chunks plus reload suffice for this immutable slice. No WebSocket, mutable delta stream, interest checkpoint/outbox delivery, construction or private grant events are claimed implemented. WF2/WF3 must implement those contracts before mutable multiplayer claims. Two clients/reload and fresh pool/app instances read identical persisted state now.

`withTopologyGuard` is a retained internal transaction primitive with bounded lock wait, not a public mutation endpoint or authorization grant. The two-corridor PostgreSQL experiment uses the same graph validator to prove shared connectivity needs serialization even for disjoint obstacles. Independent non-topology rows remain writable while the guard is held. Future mutations must acquire policy scopes before this guard and validate their full spatial dependencies; the experiment is not a completed construction subsystem.

## Renderer and supported profile

Actual app routes: `?founding=fern/hearth/brook` for labeled examples; `?founding=new` for explicit founding; `?world=<v2 UUID>` for saved v2; `?village=<v1 UUID>` unchanged. Existing React shell, Pixi WebGL surface, demand camera and asset loader are consumed. No study-only replacement viewer is the deliverable.

Terrain graphics are built per chunk from persisted samples, with1/2/4-cell LOD based on semantic zoom. The bounded interest/cache moves with the camera; coarse geography and near terrain share the same fields. Camera bounds keep the finite storage edge outside ordinary exploration; no floating rectangular base or infinite zoom-out is exposed. Current interest is a square band and synchronous mesh rebuilds can hitch; this is not final terrain art or a general streaming engine. Mesh/material/profile refinement may change appearance without changing authoritative heights or natural features.

Projection is `((x-y)*32,(x+y)*16-z*32*sqrt(1.5))`; this matches retained Blender B(x,y,z)=(y,x,z),45° plan/30° elevation. The H01 original shelter and apple tree are reused unmodified. Source width2560/ortho_scale22 gives82.28 horizontal pixels per local unit; actual ground posts fit the independent3×2 support footprint, with small visual roof overhang. Overview and focused crop share source geometry/materials; focus changes resolution/composition, not world identity. Gentle-bank/negative/cross-chunk/height-aware projected-triangle picking is retained; cosmetic ground inspection grants no interaction permissions.

Painter depth is supported only for non-interpenetrating assets on this gentle profile. Dense canopy crossings, tall retaining walls, layered deck surfaces and arbitrary complex structures are **not verified**. One shelter cannot prove mature-town occlusion. Natural-cover labels are separate from active territory; the founding territory is a logical radius, not a drawn physical platform. No activation command, path edits, grading, buildings or rewards are enabled.

Textures are finite pinned shared resources: base about2.45MiB, focused detail cached total about3.74MiB decoded RGBA. Report includes the cached detail after reset; it is not falsely counted as freed. CPU/GPU copies, geometry and framebuffers are additional. Actual heap/mesh timing and platform limitations are in evidence. H01 artistic identity and the full CV-S1 visual gate remain unapproved.
